# how-to

- [Build a status line row of your own][sokf:how-to-build-a-status-line-row] - Read the JSON fields of `smllm statusline` and print a row of your own in place of the default.
- [Check machine files in your editor][sokf:how-to-check-machine-files-in-your-editor] - Point your editor at the JSON Schema of the machine format, so that it completes the keys of a machine file and marks a wrong key as you type.
- [Drive smllm from a script][sokf:how-to-drive-smllm-from-a-script] - Start a session, fire events, and read where the session is from a shell script or from a harness without MCP, with JSON output and exit codes.
- [Name work by your issue id][sokf:how-to-name-work-by-your-issue-id] - Give each instance of a machine the id of its issue, so that you and the agent find the work by the id that you already use.
- [Pause and resume work][sokf:how-to-pause-and-resume-work] - Put an instance aside, find it in the idle list, and pick it up again later, in the same session or in another.
- [Read the audit of a session][sokf:how-to-read-the-audit-of-a-session] - List every call that drove a session, accepted or refused, to see what the agent did and where smllm stopped it.
- [See a machine as a diagram][sokf:how-to-see-a-machine-as-a-diagram] - Print the states and transitions of a machine as text or as a Mermaid diagram, open it in your browser, or write it to an HTML page or a PNG picture.
- [Show smllm in your status line][sokf:how-to-show-smllm-in-the-status-line] - Add a row to Claude Code's status line that shows the state machine, the state, and the instance of the session.
- [Take JSON in a param][sokf:how-to-take-json-in-a-param] - Give an event a param that takes a JSON value, such as a plan with a list of steps, and describe its shape with a JSON Schema.
- [Use your machines in every project][sokf:how-to-use-your-machines-in-every-project] - Keep state machines in your user config, so that every project on your computer can run them.
